# 决策②：转换管线 = 全自动服务端管线（无人值守）

宿主 2026-09-10 回答（问题 2，选项 A）：

> **「上传 → 解析 → 逐块翻译 → 产出可读中文文档，全程无人干预，失败只标记状态可重试。目标是『一键、批量、可无人值守』。」**

## 含义（对设计的硬约束）
- 转换是**服务端任务**，必须有任务队列 + worker + 状态机（`none/doing/done/failed` 四态扩展到可重试）
- **不设人工验收环节**：现有 pku-paper-3d 流程里「宿主逐篇 `open` 浏览器人工验收才 commit」这一步**被产品化掉**
  - → 正确性保证必须**内建在管线里**（自检/校验），不能依赖人眼
  - → 但「失败标记可重试」意味着仍然允许人工**触发重试**，只是不做逐篇校对
- 批量：一次上传多篇，排队并行/串行处理，前端展示转换队列进度
- 与原型一致：文献库里的 `cv`（转换态）字段 + 导入抽屉里的「转换队列」

## 问题 3（进行中）：转换引擎形态
助手给出四选项，并**明确推荐 C（混合）**；宿主尚未作答：
- **A 本地解析器 + LLM 逐块翻译**：用 PyMuPDF（宿主已有）/ MinerU / Docling 出**版面骨架**（栏/块/图/表/公式 + 坐标），文本**逐块**送 LLM 翻译，再由程序按原始坐标重装成双栏 HTML。快、便宜、可复现、可增量重试，**公式与数字不会被改写**；段落有稳定 ID → 阅读器的段落选中 / 笔记锚点 / 三态切换天然可做。天花板 = 解析器的版面还原能力。
- **B VLM 端到端**（每页渲染成图 → 多模态模型直出结构与译文）：复杂版式鲁棒、实现最短；但贵、慢、不可复现，**幻觉会改写数字/公式/引用**（论文里是致命伤），段落级锚点难做。
- **C 混合（推荐）**：解析器出骨架与版式，文本走 LLM 逐块翻译，**仅对解析器搞不定的部分**（跨栏大图、复杂表格、公式密集页、扫描件）调 VLM 兜底。兼顾成本与鲁棒，且疑难路径可单独度量与迭代。
- **D 现成文档 AI 服务/模型**（MinerU / Docling / LlamaParse / Mathpix / 云厂商文档解析）：解析外包、翻译接 LLM。省事，但引入外部依赖与费用 —— 对**要自托管的开源项目**需要权衡。

→ 宿主回答后再落为正式决策（新建 `decision-conversion-engine.md`，或并入本文件）。
