# 决策⑩：只读分享 = 实时只读视图（**不是快照**）

宿主 2026-09-10 回答（问题 10）：

> **「分享链接不是快照。而是和分享者看到的是相同的页面，只是没有操作权限，无法上传、标识进度等。只能看。场景是：同学之间互相监督、互相学习、给导师汇报进度等等。」**

## ⚠️ 对原型的重大修正
原型实现是 **URL 内嵌快照**（`shLink` value = base64 编码的计划数据，`shHint`：「链接包含该计划的快照数据，较长属正常」；前端 `SHARE.active` 时禁止写 localStorage）。
**这套机制整个弃用。**

## 确定
- 分享链接 → **服务端承载的一次实时渲染**，打开即看到**与分享者当前所见相同的页面**
- **实时**：分享者更新（新增文献、推进进度、加笔记、转换完成）→ 访问分享链接的人**刷新即看到最新**，不是冻结副本
- **只读**：访客无操作权限 —— 不能上传/导入 PDF、不能改阅读状态与进度、不能编辑笔记
- 分享粒度 = **单个阅读计划**（对应原型顶栏「分享计划」按钮）
- 场景驱动：同学间互相监督/互相学习、给导师汇报进度

## 与决策①「用户间完全隔离」的关系（不冲突）
- **隔离**约束的是**写**：谁也改不了谁的数据 → 只读视图不破坏它
- **分享**放开的是**读**：特定计划对外可见
- 层级仍为 User → Plan → Paper，**不引入 Team/Org**

## 实现要点（待细化）
- 需要服务端 **share token → plan** 的映射表（区别于原型的一次性序列化）
- 前端只读模式：隐藏/禁用所有写操作入口（导入、勾选进度、笔记编辑、拖拽看板）
- 待定：匿名访问 vs 需登录；token 撤销/有效期；分享范围（整个计划 vs 单篇文献）

## ⚠️ 需正面面对的风险（开源项目）
公开链接会暴露**整篇论文的中文全文**（阅读器页包含译文）。这是无鉴权分发第三方版权内容的行为，**版权风险由部署者承担**。原型对此未作任何提示。→ 需在文档/README 明确警示，并考虑访问控制（见下一问题）。
