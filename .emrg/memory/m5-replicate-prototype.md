## ⚠️ 被推翻的判断（助理原文档写错，留证）

`docs/design.md` §6 原写：总览/文献库/看板是「**跨计划**的全局视图」，v1 没做是"刻意收窄"，
留待 M5 等真有跨计划需求。**这是错的。**

回原型核对（`/Users/argszero/Downloads/t1/literature-workbench.html` L1479–1483）：

```js
const activePlan = () => state.plans.filter(p => p.id === state.activePlanId)[0] || state.plans[0];
const papers  = () => activePlan().papers;      // 总览/文献库/看板/阅读器 全部取数都走这里
const S       = { get: p => activePlan().status[p.id], set: (id, v) => { activePlan().status[id] = v; } };
```

→ 原型**没有跨计划聚合**。侧栏计划切换器切的是**当前计划**，整屏数据随之更换。
→ 所以「v1 没做」不是刻意收窄，而是**漏做**；当时的错误判断还被我写进文档当成了设计依据。

**教训**：把"没做"归因成"刻意不做"之前，必须回原型核对取数函数；文档里的自证式说明
（"我们刻意收窄"）会掩盖真实缺口。

## PDF 分页容器 —— ✅ 已落地（宿主 2026-09-11 选 A）

原型阅读器把文档渲染成 **PDF 页框**：`<section class="pdf-page">` + 页脚「第 N 页 / 共 17 页」
（`docHTML()`，L1812）。**现已真分页**：

| 层 | 改动 |
|---|---|
| 解析 | **每个块**盖 `payload.page`（`parse.py` 的 `_paged_adder`）。原先只有 `figure` 有页码（循环里手写的那一处）→ 只能渲成一条流。同页内 `section` 会变，所以 `section` **调用时**传入、不提前定格 |
| 缓存 | `doc_cache` 指纹改为 **sha256(pdf) + `PARSE_VERSION`**（`parse.py` 常量，改动解析产物形状时手动 +1）。**不加减这个，分页永远不出现**：PDF 没变就永远命中旧解析产物，代码看着完全正确 |
| 渲染 | `pages/PagesBody.tsx`（`<Page>`）+ `pages/pageGroups.ts`（纯函数 `groupByPage`，分出来是为了 Fast Refresh）；阅读器 / 分享页 / 导出 HTML（`synth.synth_dual`）**三处同版式**；**标题区跟在第一页**（原型 `idx === 0` 才渲 `doc-head`） |
| 降级 | 老文档（无 `page`）→ 全篇一页、页脚不显页码，**内容一块不少**（有回归测试） |

**代价（已如实告知宿主）**：已转换的文献要**重跑管线**才带页码 → 会再花一次 LaTeX 化 + 翻译的 token。

### 顺带修掉的真缺陷：懒加载图无宽高 → 大纲跳转偏位约 7,500px

`figure` 的 `img` 只有 `loading="lazy"`、没有 `width`/`height` → 未加载时高度≈0，
滚到哪长到哪，整篇高度事后上浮约 **7,300px**（实测 65,407 → 72,619）。
于是「大纲跳转」`scrollIntoView` 在**布局还在长**的时候算目标位置，跳完落在页中间：
点「VIII. 结论」（第 13 页）后目标块 top=7657px，离视口（高 710px）差着 7000px。

**验证它不是分页造成的**：把页 section 拍平回一条流后**同样复现**（targetTop=7800）。
→ 是懒加载图的通病。修法：解析阶段在 `assets` 里另存 `width`/`height`（+ 原始像素 `ratio`），
前端给 `img` 挂这两个属性让浏览器提前占位。修后高度 79,611 → 79,635（不再漂移），跳转 inView ✅。

**⚠️ 这个占位修法埋了个连带缺陷（2026-09-11 宿主报「图片都被拉伸了」）**：
`img, svg { max-width:100% }` **只夹宽度**。原图比栏宽时，宽度被压到栏宽、
高度却仍是 `height` 属性里的原值 → **纵向压扁**。真机实测 15 张里 14 张被压 **24%~49%**，
唯一正常的是原宽 1019px（本来就没超栏宽）的那张 —— 正好印证成因。
**修法：`height:auto` 必须与 `max-width:100%` 同一条规则**（高度随宽度等比回落，
同时保住占位收益）。护栏 `tests/test_style_guard.py::test_images_keep_aspect_ratio`。

> 两条教训要一起用：**量 `naturalWidth` vs `getBoundingClientRect`** 才算数（肉眼看不准），
> 以及**护栏必须做变异验证** —— 这条件的第一版护栏被 CSS 注释骗过去了
> （注释里的 `img`/`max-width` 字样被当成选择器，改回 bug 仍然全绿），剥注释后才真生效。
> 另：验证线上效果要先 `?v=` 破缓存，否则量到的是旧 CSS（hash 文件名会骗人，但页面缓存不会自动失效）。
