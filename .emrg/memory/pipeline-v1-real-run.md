## 三条硬教训（都是实测踩出来的）

1. **校验器必须收敛**：它的输出会触发自动重译，所以每条判定都必须「重试修得好」。
   数字/公式编号/语义偏差一律降级为**警告**，只有结构性问题（缺失/多余/重复/乱序/漏译/标签不配对）才阻塞。
   *反例（已修）*：严格比数字 → 8 块烧掉 19,591 tokens 空转、永不收敛。
2. **「免中文块」必须显式豁免**：参考文献（占正文 26%）与公式/符号块（另 12%）按 prompt 规则本就保持英文，
   若不标 `data-nt` / `refs` 类型，就会被判「漏译」→ 送了不译 → 再送 → 死循环。
   **判据只能有一个来源**：`validate.expects_chinese()`，被校验器与翻译器**共用**。
3. **图注与标题再短也必须译**：判据是「实词 ≥4 个才要求中文」，而 `Fig. 2. Overall structure.` 只有 3 个实词、
   `II. FOUNDATIONS` 只有 1 个 → 会整批静默漏掉且校验发现不了。两者单列规则。
   另外标题的**编号形式**要在 prompt 里钉死（实测出现过 `I. INTRODUCTION` / `III. 安全关键控制` / `四、…` 三种混用）；
   `Fig.`/`Table` 统一为「图 N」「表 N」。

## 其他已实现的关键点

- 标题识别**不能靠字号**（IEEE 模板标题与正文同为 10pt）→ 字体 + 编号模式（`I.`+Helvetica = h2，`A.`+Helvetica-Oblique = h3）
- 图注按**几何位置**配对（跨栏大图会把图注推远；图注可能在图片**之前**）；图注并入 `en` 走翻译通道
- 文末材料（参考文献 + 作者简介）从 `REFERENCES` 小标题起标为 `refs`；出版社水印页脚直接剔除
- 对照视图 `dual` 的 `data-b` **只挂在行上**（一行 = 同 ID 中英两块），避免块标记重复/配对歧义

## 第二轮：公式 LaTeX 化（决策㉓，宿主 2026-09-10 选 B）

流程固定为 `parse → latex → translate --resume → check → export`（**LaTeX 化在翻译之前、作用在英文块上**，

## 第三轮：宿主看图后暴露的两个渲染问题（同日，均已修）

1. **大矩阵碎成一片** —— PDF 把一个矩阵抽成 **15 个独立块**（`⎡`/`⎢⎢⎢⎢⎣`/每行/`,` 各一块），
   LLM 只见碎片 → 拼出**空** `\begin{bmatrix}\end{bmatrix}`。
   → 新增 `merge_math_runs()`：解析阶段把**连续数学行**合并成一块再送 LaTeX 化。
   B5-01 合并 53 个碎片块（598 → 545），矩阵转出完整 `bmatrix` + `\tag{4}`。
   同时补齐 `˜`(\tilde) `˙`(\dot) `−`(U+2212) 等符号的检测 → 残留 Unicode 数学 **0 块**。
2. **对照视图右栏空洞** —— 免译块在中文视图**没做原文回落**（渲染成空），且并排视图给
   纯公式块**左右各渲染一遍**。→ 无译文的块改为**单栏横跨两栏只显一次**；中文视图一律回落原文。
   现在「中英皆空」的空洞 = 0。

**另修掉一个烧钱 bug**：`latex` 原本清空**所有**历史 LaTeX 化块的译文（而非本次改动的），
每修一块就重翻全篇 —— 白烧约 20k tokens/次。改为逐块比对本轮前后文本后，最后一次修补只花 **616 tokens**。

**保真校验的 6 处误判（都靠迭代修掉，值得记住）**：
1. 连字断行 `defi- nition`：模型**修好断行**反被当"文字丢失" → 比对前两侧归一化
2. 跨块拆分的展示公式（`m u + w` 与 `(35)` 是两块）`\tag` 漂到邻块 → 编号改**切片级**比对
3. 原文自身的伪影 `such thatforall`（斜体 forall 丢空格）被当内容词丢失 → 归一化 `forall`
4. 公式内 `\text{aclf}`（数学标签）被当散文词 → `\text{}` 只有 ≥2 词才算散文
5. 顺带修掉一个真 bug：`latex` 命令当时没重写 `en.html`，导致校验拿 LaTeX 化**之前**的英文版比对（苹果对橘子）
6. PDF 缺空格粘连词（`thecontrol input`）被模型拆成 `the control` 反被判丢失 → 用**整段文本的字母拼接**兜底
   （⚠️ 不能用 `prose_words` 的拼接：它只留 ≥4 字母的词，粘连词里的 "the" 早被丢掉，永远匹配不上）

## v4 更新（2026-09-10）：公式改服务端 MathML，渲染与校验分流

**触发**：骨架阶段要落地遗留项 8（公式渲染，**不得用 CDN**），并顺手发现 LLM prompt 差点被污染。

### 已完成

1. **新增 `pipeline/mathml.py`**：LaTeX → MathML（`latex2mathml`，纯 Python）。
   用 v3 的真实产物实测：**行内 366/366、展示 57/57 全部成功，0.09ms/条**，仅 1 处 `\tag` 需转写。
   产物 `en/zh/dual` 三份 HTML 现在**零 CDN、零 JS**（Chrome 109+/Safari/Firefox 原生 MathML）。
2. **`render_block(..., typeset=)` 开关**（**默认 False = 保留 LaTeX 源码**）：
   - 校验器（`validate.py`）与 LLM prompt（翻译 / LaTeX 化）必须拿源码——编号就写在 `\tag{}` 里；
   - 只有"给人看"的入口（`document_html` / `synth` / 导出）显式 `typeset=True`。
   - 默认值刻意选失败安全侧：**漏传宁可显示源码，也绝不把 MathML 喂给 LLM**。
3. **修掉一个会造成大额空烧的隐患**：`equations.py` 与 `translator.py` 构造 prompt 时用的
   `render_block` 若走默认渲染，会把整段 MathML 塞进 prompt（模型还要去猜对应 LaTeX，既贵又必错）。
4. **eq 块专用渲染路径** `render_math_block`：arXiv 路线的 `payload["latex"]` 是**裸 LaTeX**（无定界符），
   走按定界符切分的通用路径会被当散文整段转义 → 公式以源码显示。

### 真 LLM 复验（改动后，只翻 1 块 / 1 块 LaTeX 化，花费 ~2.4k tokens）

| 检查 | 结果 |
| --- | --- |
| 定点翻译含公式段落（b-0027） | 定界符 en 2 → zh 2，**保真**；整篇标记校验 ✅ |
| LaTeX 化（含 Unicode 数学的英文块） | `α ∈ (0,1)` / `k₁ ≤ 2/‖B‖` / `V̇(x)` → 全部转成 `\(...\)`，**0 残留 Unicode 数学** |

### 注意（下次改渲染前必读）

- 改 `markup.py` / `synth.py` 时，**任何新增的"给人看"渲染点都要显式 `typeset=True`**；
- 校验路径永远 `typeset=False`，否则 `\tag{n}` 丢失会成片误报（老坑：曾因此死循环重译烧 19.6k）。
