# 决策④：双语配对 = 标记穿透翻译（英文 HTML 先行，标记穿透到译文）

宿主 2026-09-10 亲自提出（问题 4 的回答）：

> **「不是生成中文 html，而是生成英文 html，并给每个块添加标记。然后整篇翻译，翻译后的结果保留之前英文的标记，是不是就能对起来了？」**

## 流水线（确定）
```
① PDF ──fitz──▶ 原文文本 + figures/ + 坐标
② 生成【英文 HTML】= 每个块带稳定标记  <p data-b="b-0042">…</p>
③ 整篇翻译 ──▶【中文 HTML】，标记原样保留 <p data-b="b-0042">…（中文）</p>
④ 按标记 zip：b-0042 的 en ↔ zh 自动配对
```

## 为什么这个设计好
- 配对**由构造保证**，无需事后段落对齐（避免中文精译合并/拆分段落导致错位）
- 翻译仍是**整篇**做的 → 保住宿主满意的译文质量（术语一致、跨段上下文）
- 块有稳定 ID → 顺带解决：**段落笔记锚点、阅读进度、单块重译、三态切换**
- 产物仍是**自包含单文件 HTML**（标记是 `data-` 属性，渲染不可见），与现有 `完整中文版.html` 形态一致
- 英文 HTML 本身还是宿主点名的缺口之一（现状英文只有 `原文.md`，无 HTML）

## 必须内建的两项（因决策②=全自动无人值守，无人眼兜底）
1. **标记保真校验**（纯程序、零成本、可判定）：
   - en/zh 的标记**集合相等** / 无缺失 / 无重复 / 顺序一致
   - 漏译检测：该块中文仍为英文 → 定位到块
   - 不达标 → **自动重译该块**（不重跑全篇）
2. **分块翻译（块边界安全）**：
   - 55 页论文整篇一次翻译必被输出长度截断（现有流程靠 `cat >>` 分块写正是躲这个问题）
   - 「整篇翻译」落实为**按标记边界切片**，块不跨切片，保证标记不断裂

## 遗留
- 产物是**两份 HTML**（en / zh）还是后台合成**一份双语 HTML**？取决于阅读器对比形态 → 下一个问题
