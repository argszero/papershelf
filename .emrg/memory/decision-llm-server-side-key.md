# 决策⑧：LLM 接入 = 服务端统一 Key

宿主 2026-09-10 回答（问题 8）：**A —— 服务端统一 Key**。

## 确定
- 部署时通过**环境变量/配置文件**配全局 LLM key（`base_url` + `api_key` + `model`）
- 全体用户**共用**同一个 key；模型与并发上限由**管理员**设定
- 用户注册即用，**零门槛**；不自备 key
- 费用由**部署者承担**，界面不做按用户计费/配额

## 结构约束
- **模型接入一律走 OpenAI 兼容协议**（`base_url` + `key` + `model`）
  → 一套代码覆盖 OpenAI / DeepSeek / Qwen / OpenRouter / Ollama / vLLM，不做厂商适配
- Key **只存服务端**，绝不下发到前端
- 既然是无人值守 + 全局 key，**必须内建成本护栏**（待设计）：
  - 并发/速率上限（避免批量上传打爆）
  - 单篇 token 预算与超限行为
  - 失败重试次数上限（避免失败任务无限烧钱）

## 关联
- 决策① 自托管多用户 —— key 由部署者提供
- 决策② 全自动无人值守 —— 费用自动发生，护栏必要
- 决策⑦ 计划私有 —— 同一论文跨计划重复翻译，成本随计划数增长
