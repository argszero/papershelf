# 待答问题④：双语配对（块级 {en, zh}）怎么生产出来

宿主 2026-09-10 在确认「沿用 s_260803_0946_bf50 管线」（决策③）时，点名两个缺口：
**① 英文 HTML**、**② 双向对比的过程**。助手据此提出设计问答第 4 题，宿主尚未作答。

→ 先读 `decision-engine-proven-pipeline.md`（决策③）与 `existing-pdf-to-zh-pipeline.md`（基线管线）。

## 问题的根因（结构性张力）
现有流程是 `fitz 提文本 → agent 整篇读完、整篇精译 → 写出中文 HTML`。
译文质量高的原因恰恰是**整篇翻译**（术语一致、指代清楚、长句按中文习惯重组）。
代价：**英中配对关系从未被显式产出** —— 中文段落是重新组织的，不是从英文段落逐块映射来的。
而原型的阅读器三态（中英对照/仅中文/仅原文）要求块级 `{en, zh}` 且 `Doc.block` 有稳定 ID。

即：**「整篇精译的质量」与「块级配对的可靠性」天然互相拉扯**，选项就是这个取舍的取值。

## 选项（助手给出，未推荐）
- **A. 先切块，再逐块翻译**（en 进块、zh 回填）
  配对 100% 精确、可增量重试、成本可控；但丢跨段上下文与全局术语一致性 → 长论文译文质量明显低于宿主满意的那一版。
- **B. 先整篇精译（保住满意质量），再段落级对齐回英文**
  译文质量不变；但需一个**对齐步骤**把中文段落映射回英文块。精译常合并/拆分英文段落 → 对齐错位，需人工兜底或降级为「节级对齐」。
- **C. 双语同生**：切块后**带全局上下文逐块翻译**（整篇术语表 + 前后文窗口喂模型）
  译文质量接近整篇精译，配对天然精确；代价是更复杂的 prompt 编排与 token 预算，工程量大一档。
- **D. 英文侧用外部现成结构**（arXiv 官方 HTML 有原生块结构），中文译文挂到其块上
  arXiv 论文省事且结构可靠；但覆盖不全（非 arXiv 无），且把版式控制权交给外部。

## 关联
- 决策②（全自动无人值守）要求**配对正确性内建在管线里**，不能靠人眼补 —— 这排除了「A 之外还靠人工对齐兜底」的随意性，B 的人工兜底与决策②有张力。
- 尚未澄清（承自决策③）：宿主满意的产物是**单栏仿期刊 HTML**，而原型阅读器是**双栏保版式**；「保版式」指内容/图表原位保真还是还原 PDF 双栏版式，仍待确认。
- 英文 HTML 缺口的落地形态（独立 `en.html`？还是同一 HTML 里的 `{en, zh}` 块？）取决于本题选项。
