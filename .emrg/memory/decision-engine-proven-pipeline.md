# 决策③：转换引擎沿用 s_260803_0946_bf50 已验证的做法

宿主 2026-09-10 回答（问题 3）：

> **「会话 s_260803_0946_bf50 是怎么做的，这个效果我还是挺满意的。只是缺少英文 html 以及双向对比的过程。」**

即：**不是一个抽象的 A/B/C/D 选型，而是「就按那条已跑通的管线做」**，并明确补两项能力缺口。

## 沿用的做法（= 事实上的引擎形态 A）
`fitz`(PyMuPDF) 解析出 `原文.md` + `figures/` + 坐标 → **LLM（agent 级）整篇精译** → 分块 `cat >>` 生成**单文件仿期刊中文 HTML**（MathJax CDN + 相对路径图 + 锚点目录）。

## 宿主满意的"效果"具体是什么（实测产物 B5-01-CBF-review）
目录：`original.pdf` + `原文.md`(fitz 提取，带 `--- 第 N 页 ---`) + `figures/` + `完整中文版.html`
- 单文件 HTML，824 行 / 109 KB，`<html lang="zh-CN">`
- **单栏**（`.page` max-width 940px），仿 IEEE 期刊风（页头栏名 + 中英标题 + 作者/DOI）
- 结构元素：12 个 `h2.sec` + 17 个 `h3.sub` + 21 个 `<figcaption>` + 8 个 `<table>` + 脚注锚点
- **公式**：`<div class="eq">\[ ... \tag{N} \]</div>` —— LaTeX 原文保留 + 编号，MathJax 渲染
- **图**：`<figure class="wide"><img src="figures/fig3_cbf_concept.png"><figcaption><strong>图 3</strong>　…</figcaption>`
- **英文仅在标题与个别术语括注中出现，正文全中文**

## ⚠️ 由此暴露的一个歧义（待澄清）
宿主满意的产物是**单栏仿期刊**，但原型阅读器是**双栏保版式**（`span:full` 跨栏块、块保留原始栏位）。
「保版式」到底指"内容/图表原位保真"还是"还原 PDF 双栏版式"，尚未确认。

## 两项新增能力（宿主点名的缺口）
1. **英文 HTML** —— 英文侧也要有可读的 HTML 形态（现状：英文只以 `原文.md` 存在，无 HTML）
2. **双向对比的过程** —— 原型阅读器有 中英对照/仅中文/仅原文 三态，块级 `{en, zh}`；
   现有流程只有中文稿，**英中配对关系并未显式产出**，需要设计"双语配对"的生产方式
