# 决策⑦：文献归属 = 计划私有（沿用原型做法，不做跨计划共享）

宿主 2026-09-10 回答（问题 7）：**B —— 不共享**。

## 确认的事实（宿主自己观察到并去代码核实）
宿主提问：「我看原型是在某个计划内才有导入 PDF？导入 PDF 按钮在『分享计划』按钮旁边」——**观察正确**。
原型代码证实导入是**计划作用域**：
```js
const pl = activePlan();                     // 当前计划
pl.papers.push(p);                           // L2133 文献进计划
pl.queue.push({ name, meta, st:'queued' });  // L2134 转换队列也进计划
toast('已加入 N 篇到「' + pl.name + '」');    // L2143
```
且 `DOC.paperId = 'attn'` —— 文档模型挂在计划内的某篇 Paper 下。

## 确定
- **导入入口**：保持「在计划内导入 PDF」（顶栏右侧，与「分享计划」并排）
- **数据归属**：文献属于**计划**，计划各自持有副本；同一篇论文出现在两个计划 = **两条独立记录**
- 阅读状态 `st` / 进度 `pr` / 转换态 `cv` / 笔记 `notes` 均**随计划内的文献记录**（不跨计划）

## 接受的代价（宿主已知）
- 同一篇论文在不同计划中需**重复存储**与**重复翻译**（LLM 成本翻倍）
- 「这篇论文我到底读过没」在不同计划间会分裂成多份状态
- 缓解余地（未决策，非当前问题）：可按 PDF hash 做**翻译结果缓存/去重**，在不改归属模型的前提下省掉重复的 LLM 花费

## 附带的简化
决策⑦选 B 后，原先担心的子问题「阅读进度/笔记挂在文献上还是『计划×文献』上」**自动消解**——因为文献记录本身就是计划私有的，不存在两层。

## 与决策①的关系
宿主已定「自托管多用户、用户间完全隔离」→ 归属层级为 **User → Plan → Paper**（无 Team/Org 层）。
