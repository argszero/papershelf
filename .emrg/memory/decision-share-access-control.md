# 决策⑪：分享访问控制 = 持链接即可访问 + 可撤销/可设有效期（不做密码）

宿主 2026-09-10 回答（问题 11）：**「A+D」**，并复述确认：「A 起步 + D 的撤销/有效期（不做密码，避免又要传密码）」。

## 确定
- **A**：**持有链接即可访问，无需登录** —— 链接本身即凭证（长随机 token，不可猜）
- **D**：**可随时撤销** + **可设有效期**，**不做访问密码**（避免又要在聊天里传一个口令）

## 为什么不做密码
宿主明确：「避免又要传密码」。撤销/有效期已提供"泄露后止血"的手段，密码只是多一个要传递的凭证，收益低。

## 为什么不能强制登录（推论已确认）
分享场景含**给导师汇报**，导师不会为看进度去注册 → **匿名读路径是必需项**，纯"必须登录"方案不可行。

## 与决策①「用户间完全隔离」不冲突
- **隔离**约束写：谁也改不了谁的数据
- **分享**只放开读：且只对**被显式分享的那个计划**放开
- 层级仍为 User → Plan → Paper，**不引入 Team/Org**

## 仍需在实现中内建（安全要点）
- token 足够长且随机（不可枚举）；撤销即服务端立即失效
- 有效期到期自动失效
- 只读：访客**不能**导入/改阅读状态/改进度/编辑笔记（前端禁入口 + **后端校验**，不只靠前端隐藏）
- 分享粒度 = 单个计划
- 撤销/过期后的链接应返回明确提示而非 404 哑失败

## ⚠️ 版权风险（仍未闭环）
公开链接会**无鉴权分发论文中文全文**。这是开源项目要正面提示部署者的风险：
- 需在 README/文档中明确警示（部署者需自知在公开分发第三方版权内容）
- 撤销/有效期是本问题的缓解手段之一，但不改变"链接期间公开"的性质
