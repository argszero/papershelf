# 问题⑭「谁能注册这个实例？」—— ⏳ 待宿主作答

**提问时间**：2026-09-10（⑬「v1 全做」归档后立即提问，宿主尚未回答）。

## 为什么必须现在定
决策①（自托管多用户）与决策⑧（LLM Key 服务端统一、费用由**部署者**承担）叠加 →
**「谁能注册」直接等于「谁在花部署者的钱」**。开放在公网的实例若无门槛，任何人都能用部署者的 key 烧钱。

## 选项（已给宿主）
- **A. 完全开放注册** —— 谁访问到站点谁就能注册即用 → 公网实例上任何人可烧 key，除非只在内网跑
- **B. 默认关闭注册，管理员后台开号** —— 最安全、职责清晰；但「多用户」退化为「手工发号」，小规模（自己 + 几个同学 + 导师）正合适
- **C. 邀请码** —— 管理员生成邀请码、持码自助注册；兼顾自助与可控，代价是多一套邀请码管理
- **D. 可配置（助手推荐）** —— 环境变量控制：默认 `注册关闭`，可打开并设「仅前 N 个用户」
  → 开源项目该有的样子：**默认安全，部署者自行决定**。宿主场景（自己起实例 + 几个同学）默认关闭即可

## 助手立场
**推荐 D**：出厂默认关闭注册 + 管理员开号，同时留环境变量开关给「想开公开实例」的部署者（与 ⑧ 的成本护栏互补）。

## 配套的实现细节（助手明确不占用问题额度）
注册/登录的**会话机制**（cookie session vs JWT）属实现细节 →
助手倾向按 Python 单体（决策⑨）用**签名 cookie session**，除非宿主另有偏好。
