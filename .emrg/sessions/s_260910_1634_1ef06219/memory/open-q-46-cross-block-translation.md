## 一、先更正我自己的一个错误结论

上一轮我报「**跨页 0**」—— **是我扫错了**：我只比较**相邻两块**，而跨页处中间必然夹着页眉块

## 二、宿主截图那一例（生产 paper 2）的真凶：**不是"没给上下文"**

`b-0026`（p2 末）「…the same statistical quality assurance that can be achieved with traditional manufacturing」
→ `b-0027`（p3 页眉，`band`）→ `b-0028`（p3 首）「processes. Therefore, it has frequently been identified…」

已给上下文（`translate_blocks` 早就传了 `before`/`after`），但有三处**具体**的失效：

1. **上下文取错邻居**：`before = ordered[first-1]` 是**裸相邻** —— 跨页处交给模型的「上文」
   其实是**页眉**（`Journal of Intelligent Manufacturing (2024) 35:1407–1437 1409`）。全库 **24 次**。
2. **这一例两半其实在同一个切片里**（chunk 3 = `b-0026/0027/0028`）⇒ 模型**看见了两半**仍然译断：
   输出必须与输入**块数相同、顺序相同**（`data-b` 一一对应是硬约束），而提示词里**没有一条**
   说"这两半是同一句、中文必须在同一位置断开"。
3. 另有 **12 对落在切片边界**上（chunk 切在接缝处）⇒ 两半模型都看不见。

## 三、可走的方案（等宿主选；我倾向 A）

- **A｜上下文取"最近的正文邻块" + 提示词加一条「半句接缝」规则**：
  跳过页眉/装饰再取 before/after；切片内部把接缝标出来（如块级 `data-cut`），
  并要求中文在**同一位置**断开。改动局限在 `translator.py`，不碰块 id ⇒ 笔记/划痕零风险。
- **B｜翻译前把半句对合并成一块**：会改块 id ⇒ 笔记与划痕要搬家，且与 ㊲ 的既定分工冲突
  （㊲ 定的是"解析层只标记、由 ①c agent 看图决定 `merge_block`"）。
- **C｜A + 扩大上下文窗口**（前后各 2–3 块）：更贵，收益未验证。
- **D｜交给 ①c 校对 agent 兜底**：它本来就能 `merge_block`，但**跨页合并是否被工具允许未验**
  （㊲ 实现是"并入**页内**上一块"），且 ①c 只在转换时跑一次，存量文本吃不到。

## 四、顺带发现（与 ㊲ 的关系）

`payload["seam"]` 的判据是**栏间几何** + 文字两条同时成立 ⇒ **跨页那一类根本没被标记**
（生产 paper 1 只有 1 个块带 `seam`）⇒ ①c 从不把它们当可疑对象。若要 D，先得让跨页也进标记。
